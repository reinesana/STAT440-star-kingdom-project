## 目的

配管が漏洩した場合に発生する `Cost` を、trainから推定するためにモデルを作成する必要があります。そのモデルを学習させるためのデータがtrain_predict_cost.csvです。

学習したモデルに、pipe IDを入れます。学習済みモデルはpipe IDを使って、そのパイプの場所や長さ、取り換えの時期を入手し、それを学習済みモデルに与えます。

学習モデルはそのパイプを交換するときの予測コストを算出して教えてくれます。


- trainから欠損がある6件（すべて敷設日欠損）を除外し、**14,107行**を収録。
- 外れ値として削除・上限処理していません。
- 期間は2019年1月6日～2026年12月31日。
- trainデータのpipe IDをpipes.csvのpipe IDと一致させて、データを合併した。
- データ合併後にTakitoがモデル学習に必要そうだと感じた特徴量を作成し追加た。

## データの前処理

| 処理 | 内容 |
|---|---|
| データの結合 | `train.csv`の`Pipe ID`に対応する属性を`pipes.csv`から追加。trainの14,113件すべてが一致。 |
| 欠損行の削除 | 結合後、元の11カラムのどれかが欠損している行を削除。**敷設日欠損の6件を除外し、14,107件に**。 |
| 使用年数の計算 | **漏洩日−敷設日の日数を365.25で割る**。365.25はうるう年を近似的に考慮した1年の日数。敷設時刻が不明なので日付単位で計算し、小数年を丸めず保持。 |
| 行の並べ替え | **`pipe_id`の昇順**で保存。 |

## 各カラムの意味と必要性

| **カラム内容・計算方法必要性・学習での役割** |                           |                                               |
| ------------------------ | ------------------------- | --------------------------------------------- |
| `pipe_id`                | 元のPipe ID                 | 他データとの結合、予測結果の追跡用。基本の説明変数にしない。                |
| `date`                   | 漏洩日（YYYY-MM-DD）           | 管齢・季節・暦年の計算、年別の検証用。日付文字列をそのまま入力しない。           |
| `time`                   | 漏洩時刻（HH:MM）               | 原記録の保全用。基本モデルでは使わず、将来シナリオにも時刻は要求しない。          |
| `cost`                   | 記録された費用                   | **目的変数y**。説明変数Xには入れない。費用の通貨・内訳はCSV単独では確定できない。 |
| `lay_date`               | 交換前配管の敷設日                 | 管齢を計算する元情報。日付文字列自体は基本入力にしない。                  |
| `material`               | 交換前素材の文字列                 | 素材による費用差を学習。カテゴリ対応モデルで使用。                     |
| `surface`                | 地表区分の文字列                  | 地表による工事条件・費用差の候補。カテゴリ対応モデルで使用。                |
| `gps_x1`                 | 始点のx座標                    | 元の形状情報の保全、長さ・中心の計算用。基本モデルでは中心座標を使用。           |
| `gps_x2`                 | 終点のx座標                    | 同上。                                           |
| `gps_y1`                 | 始点のy座標                    | 同上。                                           |
| `gps_y2`                 | 終点のy座標                    | 同上。                                           |
| `pipe_length`            | sqrt((x2-x1)^2+(y2-y1)^2) | 配管の規模を表す。端点を結ぶ直線距離であり、曲線の実延長ではない。             |
| `log1p_pipe_length`      | ln(1+pipe_length)         | 長さの非線形な関係を試す候補。元の長さと選択・比較する。                  |
| `years_used_at_leak`     | (漏洩日−敷設日の日数)/365.25       | 漏洩時点の管齢。日数は日付単位で計算し、小数年は丸めず保持。                |
| `log1p_years_used`       | ln(1+years_used_at_leak)  | 管齢と費用の非線形な関係を試す候補。                            |
| `midpoint_x`             | (x1+x2)/2                 | 配管の代表位置。素材・地表だけでは表せない地域差の候補。                  |
| `midpoint_y`             | (y1+y2)/2                 | 同上。                                           |
| `event_decimal_year`     | 漏洩年＋その年の経過日数/その年の日数       | 年をまたぐ費用変化を表す候補。物価指数そのものではない。                  |
| `event_month` | 漏洩月（1〜12） | 月ごとの費用差を学習する候補。将来はシナリオの日付から計算する。数字の差は季節の距離を正しく表さないため、季節のsin/cosも保持する。 |
| `season_sin`             | sin(2π×その年の経過割合)          | 季節性。年末と年始が近いことを表す。                            |
| `season_cos`             | cos(2π×その年の経過割合)          | sinと組にして季節の位置を区別する。                           |
| `material_code`          | 素材の固定整数コード（下表）            | カテゴリを整数で指定するモデル用。順位・距離の意味はない。                 |
| `surface_code`           | 地表の固定整数コード（下表）            | 同上。                                           |
| `material_brass`         | brassなら1、それ以外0            | 真鍮を表す素材フラグ。                                   |
| `material_cast_iron`     | cast ironなら1、それ以外0        | 素材ラベルcast ironを表すフラグ。                         |
| `material_copper`        | copperなら1、それ以外0           | 銅を表す素材フラグ。                                    |
| `material_gray_iron`     | gray ironなら1、それ以外0        | 素材ラベルgray ironを表すフラグ。                         |
| `material_wrought_iron`  | wrought ironなら1、それ以外0     | 錬鉄を表す素材フラグ。                                   |
| `surface_farmland`       | farmlandなら1、それ以外0         | 農地を表す地表フラグ。                                   |
| `surface_grassland`      | grasslandなら1、それ以外0        | 草地を表す地表フラグ。                                   |
| `surface_road`           | roadなら1、それ以外0             | 道路を表す地表フラグ。                                   |
| `surface_structure`      | structureなら1、それ以外0        | 構造物の地表区分を表すフラグ。                               |
| `surface_swamp`          | swampなら1、それ以外0            | 湿地を表す地表フラグ。                                   |
| `surface_water`          | waterなら1、それ以外0            | 水域を表す地表フラグ。                                   |

モデルは言語を扱えないので、surfaceがwaterと言われても理解できない。
そこで、surfaceのカラムをwaterなら1, swampなら2という列を作ることを考えたが、そうすると学習モデルはwaterよりもswampの方が数字が大きい何かと考えてしまう。（身長のように順序があると認識する）。なので、surfface_swampやsurface_waterという列を作り、waterなら1,それ以外なら0というような列を各カテゴリカル変数で作った。
log(変数)となっている列もいくつか作った。例えばサンプルが[1,2,1000]だと、1000に引っ張られてモデルが学習してしまうという失敗を防ぐために、正規化という処理を施したものである。
season_cos, season_sinという列も追加した。これは1月と2月は隣の数値として使えるし、実際に1月と2月の気温や湿度は変わらないので良い挙動である。しかし、1月と12月も気温や湿度は似ているのに、12-1=11月分離れている。こうなると、コンピュータは全く別の季節として1月と12月をカテゴライズしてしまうから、sinやcosといった円にすることで、この問題を解決している。

## 注意事項
モデルを学習するときに、同じようなカラムをいくつも入れるとそれに対して過学習を行うことがある。例えば今回のプロジェクトで、学習データのカラムが時間に関するカラムが１０列あって、長さに関するカラムが１列しかなかったら、モデルは時間のみを使ってコストを予測するようなモデルになってしまう可能性がある。
なので、今後あなたが特徴量を追加したいときや、私が作った特徴量を使う際にはchat GPTなどと相談して、どの特徴量を使うべきかを相談しながら使用してほしい。

## 検証方針

各自がコストを予測するモデルを作成する。
そのモデルを、5-foldでRMSEの平均とばらつきを確認し、比較します。

5-foldとはtrainデータを5つに分けて、４つを実際のtrainデータとして使い、残りの一つをtestデータとして使うことです。学習済みモデルを使って、コストを予測させて、testデータの実際のコストとの差をとり、２乗して√をつけることでRMSEという指標を得ることができます。これは、予測と正解がどれ位離れているのかを見ることができます。
RMSEのメリットは1^2=1だけど、2^2=4となるので、予測した値と正解の値が大きければ大きいほど、誤差としての値が大きく計算されます。
また、コストがもともとCADならRMSEもCADで計算できるため分かりやすいです。

データ1,2,3,4をtrainとして使い、データ5をtestとして使う。
データ1,2,3,5をtrainとして使い、データ4をtestとして使う。
ということを５周行い、testデータでどの程度高い精度でtestを予測することができたのかを調べます。

最終的に5つのRMSEが得られるので、これを平均したら、そのモデルの精度が分かります。この値が大きければ大きいほど、予測が正解とずれているという事になります。
